# GitHub CI notes — GalaxyXR-Driver (2026-10-10)

Portable description of `.github/workflows/` so the same design can be lifted into another repo.
Sources read: `release.yml`, `build-tools.yml`, `open_pull_request.yml`, `dependabot.yml`,
`tools/release-policy.cjs`, `tools/verify-release-version.cjs`, `tools/Verify-ReleaseVersion.ps1`,
`tools/publish-release.cjs`, `tools/Package-GitHubRelease.ps1`.

## Shape

| Workflow | Runner | Trigger | Permission | Purpose |
| --- | --- | --- | --- | --- |
| `release.yml` | windows-latest (60 min) | push any branch + `v*` tag, PR, manual dispatch | `contents: write` | full build + test, then version/publish |
| `build-tools.yml` | windows-latest (20 min) | push any branch, PR, dispatch | `contents: read` | toolchain/installer + service suites only |
| `open_pull_request.yml` | ubuntu-latest | push to `dev`, dispatch | `pull-requests: write`, `contents: read` | auto-open `dev` → `main` PR |

Both Windows jobs set `concurrency.group` per `github.ref`; release uses `cancel-in-progress: false`
(releases must finish), build-tools uses `true`.

## `release.yml` — build and publish

1. `actions/checkout@v7`, `fetch-depth: 0`, `submodules: recursive` (history needed for version diffing).
2. `actions/setup-node@v7` Node 22, npm cache keyed on the GUI's `package-lock.json`.
3. `node tools/release-policy.cjs` (step id `policy`) → computes next version, writes `CHANGELOG.md`, emits `publish`.
4. `node tools/prepare-native-dependencies.cjs` then `--check` — restore vendored native deps, then preflight.
5. `dtolnay/rust-toolchain@stable` (target `x86_64-pc-windows-msvc`) + `microsoft/setup-msbuild@v3` x64.
6. `tools/Verify-ReleaseVersion.ps1 -Tag $tag -PassThru` → `version` output; fails if the tag doesn't match source.
7. NVENC bypass regression tests run in `cmd` after sourcing `VsDevCmd.bat` (needs a compiler env).
8. `npm ci` + `npm test` in the GUI; then seven `node tools/Test-*.cjs` service/packaging suites.
9. `node build.js --vendor neutral`, then `--vendor galaxyxr` → two staged packages.
10. `cargo test --locked --lib` in `src-tauri` (native install/cleanup behaviour).
11. `tools/Package-GitHubRelease.ps1` → ZIP, `.sha256`, release notes under `../builds/<Project>/release/`.
12. `upload-artifact` for the ZIP (`archive: false`) and the checksum + notes (`retention-days: 30`).
13. `release-policy.cjs --persist` → pushes a bot version/CHANGELOG commit, then `publish-release.cjs` → GitHub Release.
14. `if: failure()` upload of native-dependency fetch logs and reports (`retention-days: 7`).

## Release automation (the reusable core)

- **Version truth lives in the source**, not in a workflow variable. `verify-release-version.cjs` reads the C++
  `driverVersion`, the OpenVR manifest, `package.json`, `package-lock.json` (`version` **and** `packages[""]`),
  `tauri.conf.json`, `Cargo.toml [package]` and `Cargo.lock` — all must agree, else the run fails. Versions are
  changed only through `bump-version.js`.
- **Commit prefixes drive the bump**: `fix:` → patch, `feat:` → minor, `rework:` → major; anything else bumps nothing.
  (Not vanilla Conventional Commits — the mapping is project policy and is 4 lines of regex.)
- **Publish gate** (`release-policy.cjs`): publish only when the ref is `refs/heads/main` and the computed version moved,
  or the pushed tag equals `v<version>`, or a manual dispatch passed `publish: true`. Every other push/PR is a
  build-and-test dry run. Existing tags are immutable.
- **Deterministic bot commit**: fixed author/committer identity, author date = source commit date, message
  `chore(release): v<x.y.z>\n\nRelease-source: <sha>` — so a re-run reproduces the same SHA and a retry reuses it
  instead of double-bumping.
- **Publish is idempotent and fast-forward-only**: persist refuses to overwrite a concurrently advanced `main`
  (the newer run wins); `publish-release.cjs` pins the tag to the built commit, refuses to move an existing tag or
  rewrite a published release, creates a **draft**, uploads, verifies the checksum file against the ZIP bytes,
  and only then flips the release to published. A failed upload stays a draft.
- **CHANGELOG** is generated by grouping commits (Reworks/Features/Fixes/Other) and can *repair* history that was
  reverted after publication (`restoreChangelogHistory`).

## `build-tools.yml`

Independent of the release path on purpose (installer compatibility is not a prerequisite for compiling with the
runner's MSVC). Verifies build sources are tracked (`verify-build-sources.cjs --require-tracked`), runs
`npm ci`, then `node --test` over **all** `tools/tests/*.test.cjs` in one invocation (a failing file can't hide the
others), and runs the service suites with `if: !cancelled()` + aggregated failure list so one suite doesn't mask the rest.

## `open_pull_request.yml`

`gh pr list --base main --head dev` → skip if a PR exists; `gh api .../compare/main...dev` → skip if `total_commits == 0`;
else `gh pr create`. Fails with an explicit `::error::` if Actions PR creation is disabled.

## Porting checklist

- Runner labels, action majors (`checkout@v7`, `setup-node@v7`, `upload-artifact@v7` — confirm those majors exist
  upstream and pin real tags before reuse), Node version.
- Hardcoded paths: GUI `package-lock.json`, external artifact root `../builds/<Project>/...`,
  ZIP name prefix `GalaxyXRDriver-v<version>-Windows-x64`.
- Build/test entry points: `build.js --vendor ...`, the `Test-*.cjs` list, `cargo test --locked --lib`,
  `Package-GitHubRelease.ps1` — replace with the target repo's equivalents.
- `release-policy.cjs` policy block (prefix→bump mapping, `stable x.y.z` regex, prerelease rule) and the
  source-file list in `verify-release-version.cjs` (drop the GUI/Tauri/Cargo entries for a repo that has none).
- Repo settings: Actions must be allowed to create PRs; the release job needs a token with `contents: write`
  (`github.token` is used, no other secrets).
